# V2 独立前端

这是V2当前实际使用的静态目录，最初从成熟V1页面复制必要资源，后续独立维护。根 `frontend/` 仍属于V1，不修改。

入口 `index.html`，主样式 `styles.css`，基础交互 `app.js`，配单展示 `v2-components.js`，V2无模型界面 `offline-client.js`，组合入口 `site-compat.js`；`local-knowledge.js` 只供旧的显式本地模型实验模式，不默认加载。

先读 `docs/v2/FRONTEND_API_CONTRACT.md`，在前端工作区根运行 `node v2/tools/start-frontend.cjs`，浏览本机8620的 `/wiki` 和 `/huiai`。静态资源取自本工作区；API复用独立运行的V2后端，不启动另一份飞书写入。刷新页面即可看到文件修改。

前端窗口只改本目录的页面、脚本、样式与必要图片；不要改后端、飞书、运行配置、数据、V1或共享启动工具。接口缺失时记录并交给后端窗口。


## 当前结构入口（2026-10-18）

以 [结构治理交付](GOVERNANCE.md) 为准。HTML 明确加载模块；静态服务只设置 rules/offline/local 模式，不注入脚本、不修改 JS 响应。site-compat.js 为唯一组合入口，app.js 封装状态与目录，chat-controller.js 统一文字/OCR 发送；provider 显式接收 UI 依赖，会话通过事件记录，不改写 fetch 或消息函数。

以下为历史交接记录，保留溯源，其中旧加载链和阶段布局描述不代表当前实现。集成必须按治理 commits，保留其它窗口并发的软件/固件 UI 增量。

### 目录展示退化修复与后端需求

规格书、说明书接口当前均只有key=products、label=产品资料的总分组，没有一代的产品品类字段。前端取消单个总分组的额外折叠，直接展示型号与文件；不按型号猜硬件品类。规格书当前156款、521项，其中212项无url，改为不可点击并提示链接未提供，禁止href=#假链接。说明书33款、33项均有url。

软件9项缺少group/groupLabel，前端不再统称其他软件，使用软件与应用；保留所有未知分组的条目，避免后端增加分组后被固定顺序丢弃。视频实际提供12个topicGroups、78条视频，分组可用；app/cloud等内部名称换成中文或正式软件名。固件仍按20个卡型展示，取消“不确定就选通用固件”的不充分建议。

前端辅助检索折叠到搜索框下，对话模式和现场条件移到消息区上方，长原文摘录默认折叠。无需人工确认这些样式与操作修复。

交给后端窗口的具体需求（本窗口不修改后端）：
1. /api/docs?cat=spec|manual 返回一代同等粒度的产品大类groups，含稳定key、label、products及准确count/fileCount；不得把全部型号塞入产品资料/其他资料。分类应由后端已有产品元数据确定。
2. /api/software 返回已有一代group/groupLabel；当前未带字段，前端无法可靠恢复LED、手机/云、LCD等分类。
3. 为规格书目录中缺url的212项提供已登记且可访问的原文件URL，或明确不可用状态/原因。前端不推导磁盘路径或下载ID。

以上接口补齐不需要用户逐型号人工分类；涉及资料授权或来源冲突才需人工确认。现有资料不可由前端擅自筛成某个“最新/适用版本”。本轮仍不push、不部署、不修改V1。


### 速查快捷入口

搜索框后增加全文搜索按钮，直接调用既有/v2/offline/search?mode=text；搜索按钮可返回产品速查。增加工程配单链接，携带当前输入词前往独立/huiai?mode=ordering对话，空输入时只打开配单入口；不在速查页计算工程方案。手机上输入框独占一行，下方三个操作等宽。速查分类“全部”沿用产品资料范围，原始资料mode=all包含正文，两者接口范围不同。


### 后端分类接口联调复核

2026-10-17 通过8620代理核实：规格书10类156款521项，说明书4类33款33项，软件恢复led/mobile/lcd分组。现有前端直接使用后端分组，无需合并后端代码。不可用文件返回available=false、unavailableReason、unavailableMessage；前端显示后端说明并禁用操作。当前规格书182项、说明书6项暂不可用，不视为链接已全部补齐。固件20卡型96项均带链接。仅启动授权的8620前端代理，没有启动或重启后端。


### 回答模式与查询方式分离

输入框上方增加快速模式/专家模式及新查询。快速模式沿用当前无模型请求；专家模式表示本地大模型介入，在后端明确接入契约前禁用并提示待接入，不发送虚构参数、不加载local-knowledge.js。资料/案例/配单仍是独立查询方式，保留在消息区上方。后端需明确可用性、请求选择字段、介入范围、模型状态、失败与超时策略及响应证据字段，再由前端接入专家按钮。模型不替代确定性配单引擎，不由前端计算工程结论。


### 规格书重复加载等待

本机8620代理连续三轮测量：规格书接口首字节约2024～2082ms，说明书185～195ms，固件46～56ms，软件/视频3～16ms。主要等待发生在接口返回前。前端为/api/docs三类目录增加30秒页内缓存及同分类在途请求复用；错误不缓存，刷新页面即重新获取。首次加载仍由后端耗时决定，不预加载全部资料、不持久保存资料。后端窗口可排查规格书目录构建与原件可用性查询是否每次重复执行；这些仅为排查方向，前端未确认内部瓶颈且未修改后端。


### 前端易用性改进

产品搜索按钮与全部产品资料分类明确范围；全文结果和检索范围独立提示。型号文件列表默认收起不可下载项，保留数量与后端原因。阅读上下文改为原生dialog侧边阅读面板，手机全屏；支持Esc关闭、重新读取、来源定位和原文件操作，不将内部正文写入磁盘。新查询10秒内可撤销文字草稿、条件、聊天节点及原sessionId；发送文字/图片或切换查询方式后取消撤销，图片输入状态不恢复。目录版本原样展示，不猜最新版本。本轮验证真实全文/目录/原文阅读，模拟阅读失败重试与撤销，桌面及手机布局；不改后端、不push、不部署。


### 搜索按钮状态统一

产品搜索/全文搜索/工程配单统一蓝色系。实心蓝色表示当前检索范围，产品与全文切换时同步aria-pressed；配单是跳转入口，保持描边。资料分类选中也用相同蓝色。产品搜索按钮从任意原始资料范围返回产品检索，避免按钮名称与实际请求不符。
