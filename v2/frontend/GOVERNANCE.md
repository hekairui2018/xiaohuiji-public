## 实际运行依赖

```mermaid
flowchart TD
  S[static-service: 选择 rules/offline/local 属性] --> H[index.html: 明确声明脚本]
  H --> D[组件与 provider 定义：无自动初始化]
  D --> B[site-compat: 唯一组合入口]
  B --> A[app: 页面、目录、私有状态与显式 UI 接口]
  B --> C[chat-controller: 唯一发送及 OCR 生命周期]
  B --> P[选定的 offline/local 请求及展示模块]
  B --> V[conversation: 浏览器历史]
  C --> P
  P --> API[8520 已有 API]
  C --> A
  A --> E[明确的 user-message/assistant-message 事件]
  E --> V
  V --> A
```

全部脚本由 HTML 明确声明。两个 provider 只定义工厂，组合入口根据服务端已确定的模式初始化其中一个；不会因为加载 local-knowledge.js 就连接模型。组合完成后冻结 FrontendApp 顶层接口。

必要 V1 依赖清单：浏览器运行时没有根 `frontend/` 的脚本、样式或图片依赖；沿用的展示、导出、吉祥物等代码已在 V2 内独立维护。`v2-components.js` 提供确定性结果展示，`product-resources.js` 保持资料展示与链接行为，`topo.html` 为独立页面，均未机械拆分。后端内部的 V1 纯函数/飞书 writer 复用不属于前端依赖，本轮未改。
