# 业务客服与证据服务合同

本合同描述独立候选中的业务客服链路，不表示已替换当前运行服务。

## 一次理解，两种交付

公开聊天入口先执行一次任务解析与快速业务处理，再按实际选中的资料准备证据包。快答展示该次处理的确定结果，专家解释同一份依据；复杂任务可继续使用业务工具。资料检索只是工具之一，不负责替代条件配单计算或故障排查状态。

任务计划包含客户目标、已知型号/软件/芯片、已确认条件、假设和缺项，并说明解释比较、校验计算、排查、操作指导、资料定位和必要澄清等能力。能力说明不是执行成功凭证，未接通的服务不得声称已完成。

## 证据包

`evidence-packet.cjs` 只接受后端提供的授权与读取能力，不接受客户端提交的证据包。

| 字段 | 含义 |
|---|---|
| `question` | 原始问题、任务、对象、已知条件、假设与缺项 |
| `evidence[]` | 已授权文件身份、实际原文、任务摘录、适用范围及原文位置 |
| `contextComplete` | 该次上下文是否读取完毕 |
| `unitComplete` | 原生资料是否构成完整知识或操作单元，与读取完成分开 |
| `metadataOnly` | 只登记文件身份，不能支持正文参数或操作事实 |
| `outcome` | 可回答、部分依据、待补条件、范围内无记录、未解析、查询失败或尚未召回 |
| `gaps[]` | 本次仍缺的证据或条件，不能统一解释为资料不存在 |

每个候选读取前后重新核对授权，保留分页和图像依赖；最多读取两页，超过预算须标记未完，不默默截去限制条件。参数按参数单元查询，操作按目标和步骤关系筛选，资源类别和语言分别约束。只在提供了完整目录覆盖范围时允许产生“范围内无记录”。

匿名经验继续经过原有问答投影和脱敏入口；不向模型或客户恢复原件名、位置、哈希和下载入口。公开读句柄仅在当前请求有效。

## 专家与业务工具

- 有依据时优先解释、比较或指导操作，不重新搜索替换已选段落。
- 存在具体缺口时，可由模型选择检索表达，最多补查两次；后端继续限制对象、版本和授权范围，并要求阅读候选正文。
- 配单通过既有校验程序计算，未知模组只产生明确假设的条件方案，不生成现场导入配置。
- 故障保留客户观察和已完成检查；受控对照一次改变一个变量，结果只提示排查方向，不确诊。
- 文件定位和明确的必要身份确认可直接交付；响应标明实际为快答、模型调用为零，不冒充专家推理。
- 专家失败时，仅在已有已读依据可交付时显式回退快答；保留模型失败状态和实际调用数。

每项产品事实须关联已读原文，校验引用、来源片段、数值、型号和文档版次。已核实事实可以保留，未核实补充须省略并说明尚未确认。引用位置应定位到支持该句话的实际原文块，不能固定使用章节首页。

比较任务按“型号 × 所问字段”分别召回与选取，区分通信网口、屏体输出和 HDMI 等接口。快答的参数摘录从本次已读正文生成，保留跨行的限制条件并去重；专家补查后只传一份完整证据，避免工具记录重复消耗上下文。模型自行增加数值但所引用片段真实时，可改为展示该片段原文，不展示额外数值；这类回答仍标记为部分核实。

这些校验不等于独立证明语义正确。完整流程、兼容性、产品选择和故障推断仍需实际对话与原文评阅。

## 验收口径

程序契约、HTTP成功、模型成功生成、合理澄清、资料缺失和需求已解决分别统计。已参与开发的题目只能作回归；只有核实授权资料范围确实无对应记录，才能把缺失答复计为正确。新知识库表和向量检索均不能代替这种验收。
