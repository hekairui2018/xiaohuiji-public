# 日志展示与结构化上报

使用附件中“显示效果&接收卡&HDSet”的人工字段含义：

| 列 | 字段 |
|---|---|
| A | 日期 |
| B | 客户联系方式 |
| C | 技术对接人 |
| D | 区域 |
| E | 产品型号 |
| F | 版本信息 |
| G | 现场环境（软/固件版本、源端设备、线材） |
| H | 故障现象及现场操作过程 |
| I | 技术支持排查步骤 |
| J | 反馈人员 |
| K | 解决方案 |
| L | 问题状态 |
| M | 备注 |

本次程序只生成E/F，不自动写客户、过程、解决方案或问题状态。升级结束不代表客户问题已解决。云表当前视图位置与上述模板尚非完全一致；此清单是目标顺序，不是已完成的云端排版验收。

## 助手需要补充的结构字段

保留原上报接口及原有字段；不要直接调用飞书。新增字段均为可选，旧助手仍可上报。示例为合成数据。

```json
{
  "sender_model": "C16L",
  "device_code": "synthetic-device-001",
  "upgrade_run_id": "synthetic-run-001",
  "device_app_version": "7.11.50.0",
  "fpga_version": "16.18.0.0",
  "receiver_inventory": [
    {"model": "R712", "count": 2},
    {"model": "R716", "count": 1}
  ],
  "receiver_upgrades": [
    {
      "run_id": "synthetic-run-001",
      "device_id": "synthetic-device-001",
      "port": 0,
      "card_id": "1",
      "model": "R712",
      "before_version": "25.13.01.30",
      "target_version": "25.26.65.30",
      "after_version": "25.26.65.30",
      "after_confirmed": true,
      "status": "succeeded",
      "match_confirmed": false
    }
  ]
}
```

- `sender_model`：实际确认的独立型号，不含设备编号。旧`product_models`仅接受其中无歧义的独立型号；不解析`device_code`或日志正文猜型号。
- `upgrade_run_id`：本次运行唯一ID，重试不变，新运行更换。
- `receiver_inventory`：当前设备实际确认的按型号总数量，不能由固件文件数、网口数推算。缺数量省略`count`，不传0代替未知；同型号只列一次。最多256项。
- `receiver_upgrades`：本次完整逐卡采集快照，最多4096项。不能把多网口、卡号、不同运行各自的半条记录配成前后版本。
- 每条的`run_id`必须等于本次`upgrade_run_id`，`device_id`必须等于`device_code`；`port`为非负整数，`card_id`为该网口实际卡号字符串，不能自己编序号代替真实身份。
- `before_version`为升级前实际读取值；`after_version`仅填升级后同一张卡实际回读值，成功回读才设`after_confirmed=true`。`target_version`只在日志详情保留，绝不代替升级结果。
- `status`：`succeeded`、`failed`、`pending`、`matched_no_upgrade`或`unknown`。只有本次比较已确认无需升级才设`matched_no_upgrade`和`match_confirmed=true`。相同前后版本不能自动推定无需升级。
- `device_app_version`、`fpga_version`严格保持实读字符串，缺失时首次展示“未采集”，不补位数。同一明确运行及设备的晚到补充可保留已有实读发送端字段，跨运行不继承。
- `app_version`、`hdset_version`、`hdplayer_version`以及编号/机器码只在日志详情保留，不进入F。
- `receiver_upgrades`缺失时，旧`recv_versions`或`version_info`汇总不能证明逐卡对应关系；展示待确认，不猜测历史升级结果。

## 自动更新与人工保护

新记录填E/F，同时在日志详情列保存独立“自动写入基线”。之后先读取飞书当前行，逐列比较：与上次自动值一致则自动更新；不同（包括清空）则记为人工保护，只更新“自动建议-产品型号/版本信息/缺失或冲突”。E/F分别保护，不互相锁定。

旧记录无自动基线时不假定原值由程序生成，保留已有E/F，写独立建议。无法在两次同步之间观测到的人工先改后还原不计人工差异。同步程序串行处理；飞书记录API未提供本实现可用的单元格条件写入，因此人工编辑恰好与读后写入并发时仍有竞争窗口，不能声称已具备严格事务性人工编辑锁。

TXT附件和本地留底保留日志正文及结构化上报字段；云端“结构化日志详情”过长时引用完整附件，不截断原始证据。`FEISHU_SITE_DISPLAY=1`显式启用新增展示；默认旧写入行为保持兼容。生产启用必须与接收端代码更新一起进行，不能只更改云表或配置后声称现网已生效。
