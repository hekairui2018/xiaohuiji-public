# 公司资料优先的专家行为

2026-11-04。根据用户修正，专家首先是公司产品专家；确认属本行业且当前公司资料不足时，才提供有条件的行业分析。不是把“老师傅”作为无依据回答公司参数的许可。

## 通用机制

- 使用同一工作协议组织公司资料、行业推断与对话表达，不新增光纤、音视频或某软件的意图路由。
- 每轮从实际证据和工具记录生成 answerAuthority：尚未查证、候选、已有已读来源、搜索未获证据、工具失败分别标识。该状态不声称来源已经回答本题，也不把检索空结果当成资料不存在。
- recognizedObjects 传递已有解析器识别的硬件／软件类型，不在模型层另建产品分类表。
- 按动作判断指导范围：安全观察和读取已有状态可给判断依据、假设及分支；改变现场状态先核实条件与中断风险；危险或需资质的现场操作交专业人员。不限定某类故障或某条链路。
- 问候／家常自然接话，合适时轻问需求，感谢可以收尾，不反复催型号，不编个人经历。纯社交不再附加技术 JSON 动作协议；快速模式仅调整原有问候和感谢表达，不新增模型调用。
- 复用文件登记和另一窗口已经完成的文件工具接线，不增加某软件专用判断；保留原文、型号、版本及资料权限边界。

## 验证与限制

46 项定向检查通过，覆盖来源状态推进、对象类型保留、纯社交协议、并发／取消／安全、文件与配单既有接口。对投影后的实际运行模块也执行同组检查，不把未部署的工作区测试当作运行包验收。

真实 Bonsai 测试保留问候、家常、转业务、行业日志判断、公司参数依据及危险请求。问候／家常不执行工具；公司资料与推断按来源分别判断；危险请求不执行模型和工具。初次软件手册测试失败：软件名被当成硬件称呼，且文件搜索接线回落到普通正文检索。失败记录保留，随后保留已识别对象类型并恢复已有文件登记接线。

同工作区并行打包曾遗漏新依赖导致开发入口启动失败；已记录并补齐依赖，部署只投影归属修改，不复制另一窗口整个未提交文件，前端目录和其他后端模块保持原版本。恢复与运行版本、实际页面结果以私有交付回执为准。

最终开发运行 industry-mentor-04，基于最新文件交付版本保留原前端；Edge真实三轮“问候→家常→要软件手册”通过，软件手册以一次模型请求、一次工具调用直接给出两份对应原件，桌面与手机无明显溢出。源码和运行投影均通过46项检查。

另行核验的数字简称文件请求仍失败于效率及候选表达：检索112毫秒，第二轮模型约97秒耗尽4096思考Token，恢复生成后共约121秒、三轮模型请求；当时存在同题并行测试，不能与无并发旧值直接比较。此项未解决，不纳入成功结论。实际公司资料缺口回答还会追问不必要的资料名称或路径，亦保留为待改进项。

这些检查不等于掌握公司所有资料，也不是整体回答准确率；检索覆盖、模型是否遵守协议及复杂问题耗时仍需真实样本持续核验。行业判断必须有条件，不能将来源编号存在等同语义适用已获证明。未重跑原20题。

公开审查仅同步通用行为模块、合成检查和本文，不含客户原话记录、案例正文、运行包、数据库、密钥或配单策略。
