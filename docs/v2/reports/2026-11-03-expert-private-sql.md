# Expert private source tools

Expert case searches now read the existing prepared aftersales SQLite database. Tender searches read the existing tender SQLite database. The nine aftersales documents contain 668 non-context units, including cases, teaching and information; these are not 668 verified remedies. The seven tender documents contain 4,005 clause candidates. Neither database was reparsed or merged into the existing fulltext index.

Semantic retrieval embeds existing prepared fragments with the same local CPU ONNX model used by the native resource service. The private vector sidecars are bound to database and model fingerprints. The resource process shares its existing embedder through a token-protected internal endpoint. No RAGFlow or Docker service is required.

Search scope is selected by structured tool parameters, rather than symptom words. The model chooses display, equipment or unspecified focus from context. Display focus gives chip and module matches greater weight; equipment focus gives the device greater weight. Semantic similarity remains a retrieval signal, not proof of an identical fault. Explicitly different conditions and missing conditions remain distinguishable. Prepared groups, full original records, anchors, attachments, pending review status and recorded outcome text are retained.

The website adds source case cards with full historical text, relationship labels, original preview/images and original download. Read handles are issued only for returned records. Private sources and embeddings reject public or unauthenticated requests. Source fingerprints are checked before delivery. An unknown outcome review state does not override success or failure explicitly written in the original.

At the user's request only the 85°C temperature protection remains. Memory reserves, failed GPU probes and model transport errors no longer create a protection latch. Probe diagnostics are retained; model request errors still propagate. The daily operating window is unchanged.

Validation: 56 related Node tests and 10 preparation tests passed; source/asset verification passed. Fourteen ordering branch/HTTP tests passed. A pre-existing numeric-validation test also fails with the unchanged adapter baseline and is recorded separately. Real model acceptance uses the actual development website; intermediate failures and GPU probe interruption records are retained privately. Source access checks confirmed internal preview/image/original delivery and public/cross-origin/token rejection. Five real website questions returned answers with ten model calls and no page script errors. Case calls used display/equipment focus as intended, and tender calls used the tender database. This validates wiring and selected examples, not universal answer correctness. A follow-up focused check covers explicit module differences. Detailed model answers, source material and private paths are excluded from this report.

Public delivery contains generic readers, tools, embedding helpers, synthetic tests and integration patches. It does not overwrite the public core with private ordering changes. Actual development deployment and rollback records remain private.
