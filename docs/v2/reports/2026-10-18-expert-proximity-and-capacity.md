# 专家原文证据链与本地容量预算（2026-10-18）

基线为本地9d77e14上的专家链路。此前未提交的邻近检索改造继续完成；本轮容量调整不改变Bonsai的范围/关键词规划、思考档位或快速模式。仅隔离本地测试服务运行，无生产部署。

容量估计包含序列化消息与协议，另留模板余量，区别于模型响应的实际prompt_tokens，二者均记录。当前最多约120832 Token用于估计输入；不是128K输入再额外生成8K。tokenizer不可用时明确记录UTF8字节上界；容量不可核实时明确失败，不伪造模型容量。仅容量压力下移除最旧完整对话，保留当前问题、facts/checks及本轮已读证据；尚无语义摘要压缩。更早已丢失且未归档的历史不能恢复。未进行满128K压力测试。

## 原文工具实现

HTTP专家入口 → 恢复历史 → Bonsai自主search/read → 专家证据适配器 → 既有FTS5/BM25候选 → 同案例/连续段落邻近排序 → 授权read → Bonsai分析 → 来源、数值、型号及兼容性校验。

复用既有索引和案例服务，不比较不同源的原始分数。按独立概念覆盖数、同局部范围跨度排序；受控术语归一化不改型号后缀。CSV行与显式案例编号/产品型号章节分隔，避免邻例借词；无法确认的边界标明。返回原文定位、字符命中、适用条件与授权阅读句柄，未授权/歧义句柄拒绝读取。read每页6000字符，可按nextOffset继续；公司经验引用必须已读，通用建议不能藏入公司结论或具体未证实阈值。

保留基本保护：取消、服务错误、16MiB单响应字节保护、同完整参数查询缓存。同一组有效工具参数第四次提出时阻止重复（一次执行、两次缓存复用、第三次重复被阻止），不按总轮数强制模型回答。型号、版本、来源等原有校验保持；没有新增模型或依赖。

问候由真实Bonsai自然回复，无检索。C16L题由模型自主选择案例、产品、目录与技术原文，先读案例记录再读原文；随后重复搜索同一组条件，最终触发精确重复保护，**没有最终工程答案，不计质量通过**。总输入序列化最大62172字符，tokenizer估计最大25183 Token，模型实际prompt最大22633 Token；不再因32000字符或第5次调用结束。没有靠提高速度或强制最后一轮凑出答案。

独立题来自既有真实资料，模型自主search→read→answer，定位同一历史条目并转述实际处理结果；但随后建议参照记录参数调整，对现场适用条件的提示仍不足。完整原文回答和工具参数仅存内部报告。该样本有原文支持，不等于证明现场故障原因或跨型号适用。

初次扩容测试因客户端默认头部超时约300秒断开，服务端收到取消，保留失败记录（11次已完成模型调用、2次read）。修正本地HTTP传输后重新执行同题；未隐藏该次失败，不将重复回归冒充独立测试。

最终各已完成模型调用的finish_reason为stop，没有length截断或JSON格式错误。思考保持off/按需low；本次真实样本均off，reasoning_content为空，服务未提供reasoning_tokens，不能填造精确思考Token数。
