# GrayDesk fatal-error receiver

Dedicated receiver, credential, private Bitable base/table and all 17 typed fields implemented. No client changes, V1 deployment or remote-assistant release. Only software-fatal categories qualify; business outcomes and extra privacy-sensitive fields are rejected. Free text is sanitized before persistence. Clients must also sanitize before sending; pattern-based server redaction cannot recognize every possible unlabeled secret.

The receiver acknowledges only confirmed remote writes/existing events, with stable event IDs and remote idempotency tokens. Local sanitized intents recover uncertain writes without acknowledging them prematurely. Serialized writes, bounded concurrency, body limits and rate limits are included. Transport duplicates preserve manually edited processing fields and do not inflate incident counts.
