# 专家回答边界与响应协议

2026-11-04。本轮只改问答服务协议，不修改等待样式、产品速查、原始资料或确定性配单算法。

## 修改

- 统一危险现场操作边界：输入请求结合操作与电气风险判定；后续短追问参考上一客户消息。正常参数、文件和风险解释不按单个关键词拒绝。模型每轮有同一安全约束，客户文本发送前再检查；危险步骤改为转交具备相应资质的专业人员。诊断中的实际模型记录保持真实，不改成伪造的安全回答。
- clarify 协议支持有据的 claims、安全 generalAdvice 与 question；提供商约束要求明确填写可用数组，兼容原有纯追问。解码保留事实引用和追问，不再把已确认内容清空。菜单、型号参数和兼容缺对象时仍可纯追问，不强制生成通用步骤。
- 客户陈述与来源条件分开。统一工作协议明确历史 AI 不是事实、案例条件不是客户已确认事实。保留历史事实，约束把未确认案例动作转成当前操作建议的表达；明确引用转用可在本地处理，避免为删除该表达额外生成一轮。
- 计时记录总时长、排队、上下文准备、模型请求与工具执行。模型流首片段不当成客户首字；服务端实际发送文字与浏览器绘制分开，第一句结论没有可靠测量则保留 null。总处理期限同时作用于上下文、模型和工具，监控包装透传取消信号；超时停止本次请求，不暗中再调单轮模型，也不固定改成40秒。

## 验证与边界

74 项相关 Node 检查通过，含 HTTP 快速／专家统一安全边界、追问保留已知事实、来源条件隔离、输出前检查、工具超时、监控信号透传、并发、取消、上下文、文件和配单接线回归。此前基线有一个对比上下文预算失败，压缩重复提示后本轮也通过；这不是整体问答准确率。

使用实际 Bonsai（ninfer）做定向接口与真实 Edge 页面验证，开发端口与主站版本在私有交付回执中记录。危险操作及自称专业的请求在输入端转交专业人员，零模型／工具调用；菜单未确认对象时追问；故障问题有观察方向；案例回答明确原案例设备与本次未知条件。曾发现纯追问、重复表述和案例附加建议，失败轮次均保留，不只保留成功输出。

实际回答仍可能偏长，未知设备的追问也仍有冗余。安全检查由规则、模型协议和输出检查共同组成，不声称可以理解所有危险表达。案例语义是否真正支持结论仍需人工样本核验，不能把有引用等同已经证明适用。

主站实测的一条菜单题约14.9秒，一条案例题约73.4秒、3次模型请求和1次工具执行；案例最终明确区分原设备与当前未知条件，但仍可能附加追问。复杂案例耗时尚未达成可接受目标，本轮不宣称已提速。首次可见文字按当前完整校验后发送的行为计时，不是第一句结论的语义计时。

原20题的完整题面和两份原始答卷未在本工作区找到，本轮未重跑原20题，也没有新的通过率、P95或盲测成绩。首句结论时刻未测；页面首条文字不应包装成该指标。

公开范围仅通用安全／协议模块、独立合成检查和本报告。真实案例、请求与工具原文、运行配置、数据库、密钥和受控配单接线不公开；公开审查副本不等同本机完整运行包。
