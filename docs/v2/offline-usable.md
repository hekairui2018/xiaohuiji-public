# V2 本地可用版

本轮停止模型评分实验，交付实际可运行的资料、历史案例和工程配单网站。复用一代页面样式，所有适配仅位于 V2；没有修改一代前端或生产服务。

## 使用和部署

在项目根目录运行（需要 Node 18+、Python 3.11+及已获授权的现有知识快照、资源索引）：

```sh
node v2/tools/start-offline.cjs --python python
```

默认只监听本机：`http://127.0.0.1:8520/quick` 产品速查，`http://127.0.0.1:8520/huiai` 资料、历史案例与工程配单。内部只读资源服务使用本机端口8521。运行数据、会话、截图和日志进入独立运行目录，不写知识快照。

经授权的局域网使用：追加 `--lan`，多个私有网卡时用 `--lan-address` 指定实际地址。仅允许该网卡子网及本机访问，校验 Host 和浏览器来源，不信任转发地址头；资源索引8521仍仅监听本机，日志上传仍要求专用密钥。网页地址使用实际主机IP和8520端口，不把主机IP写入源码。跨电脑连通性仍取决于防火墙；网络范围控制不等于用户登录认证。

可通过 `--port`、`--resource-port`、`--index`、`--knowledge`、`--manifest`、`--data`、`--python` 指定端口和授权数据位置。默认读取候选清单，不切换 active；共享原始文件和资源数据库只读。源数据未随公开仓库提供，缺失时明确拒绝启动，不自动造数据、扫描磁盘或下载资料。

停止：终端 Ctrl+C，或 `node v2/tools/stop-offline.cjs`。停止工具先核对本机实例身份，再停止其两个进程。回退：停止此实例，回退本轮源码提交；原有实例、原始资料及 active 均不变。正式对外开放前另行确认访问权限、部署目标和数据备份。

## 实际功能

| 功能 | 本轮交付 |
|---|---|
| 产品速查 | 继续提供型号、参数、规格书、说明书、软件、固件、芯片反查和视频目录 |
| 原始资料 | 文件与正文检索、原文位置、上下文阅读；正文命中也能打开真实原件 |
| 旧链接 | 已登记资料的旧相对链接按准确文件名/已有哈希定位，找不到对应版本返回明确错误，不拿近型号替代 |
| 历史案例 | 展示现象、原文、范围、型号、版本、参考检查和历史措施；同时查已有全文索引中的原始资料，不把覆盖局限在旧2231条，也不宣布当前已修复 |
| 条件检索 | 型号/版本/芯片/扫描/点间距严格对照；范围、发生频率、时间关系、最近操作及明确否定参与候选筛选或排序；未知字段保留缺项 |
| 会话 | 原话、用户明确填写的条件、已做检查和结果、检索证据ID独立持久化；不同客户会话分开 |
| 工程配单 | 明确选择配单入口，使用现有 V2 解析、计算和校验，保留 BOM、拓扑及 SSM；不调用一代配单引擎 |
| 图片 | Windows 本地中文 OCR，图片不上传云端；识字失败可继续文字查询 |

历史案例是参考资料，不是自动诊断规则。当前底座保留312款产品、2231条历史案例；这不代表全部案例已获现场验证。没有原文的客户逐字表述、检查结果等保持未知。历史处置与本次结果分开，不把“采取某措施”解释为“已恢复”。

新接口：`GET /v2/offline/search`、`/cases`、`/case`、`/read`、`/file`、`/session`；`POST /api/ai/chat` 配合显式 `X-V2-Offline-Knowledge` 模式；`POST /v2/ordering/chat` 只接受配单。资料搜索、案例浏览与配单由用户选择，不根据关键词抢占业务路由。

案例结果包含 `facts`、`applicability.status`、`matchedFields`、`missingFields`、`notApplicable`、`sourceExcerpt`、来源位置。`facts` 保留原始表述、现象、范围、型号/芯片/软件/固件/版本、时间、最近操作、正常/异常/否定、检查动作/结果、工程判断、措施、记录结果和不适用条件的表达位置。缺失值为空；通用字面提取只是检索线索，不能取代原文阅读或复杂否定理解。

## 飞书运行日志

复用现有 `backend/feishu-bitable.cjs`，未修改其实现；V2配置、TXT、记录和 outbox 全部隔离。保留幂等 upsert、列自愈、附件上传及非空版本/芯片字段映射。不自动读取一代凭证，不做知识库同步。

把 `v2/external-services/feishu.env.example` 复制到私有运行目录并填写**经批准的V2目标表**，设置 `FEISHU_SYNC_ENABLED=1` 后重启此 V2实例。配置缺失时只留存本地，不影响主业务。后台单路异步补传，失败记录保留；查询 `GET /v2/offline/log-status` 查看状态。手动查看/补传：

```sh
node v2/tools/retry-feishu-logs.cjs
node v2/tools/retry-feishu-logs.cjs --send
```

升级助手日志可向本实例 `POST /api/huidu/log` 上报，需匹配V2配置中的 `X-Upload-Key`；未配置密钥不接受匿名上报。助手应用版本、设备应用版本和驱动芯片分别保留，不猜测版本。

本轮飞书测试使用模拟网络，真实执行原写入模块，验证断网留存、重试、去重、附件和人工字段保护；**没有写正式表，真实V2凭证及目标表尚未配置**。

## V1 → V2

- 保留：成熟页面风格、资料来源、已验证的确定性计算和飞书写入模块。
- 舍弃默认使用：一代手工意图路由、凭关键词下故障结论、模型实验控制栏。
- 新增：独立无模型启动、结构化条件与证据检索、可阅读的历史记录、隔离持久化会话、本地OCR及V2日志队列。

验证记录在 `docs/v2/stages/offline-usable-result.json`。实际网页点击、PDF下载哈希、正文/上下文、案例条件、多轮隔离、BOM/拓扑/SSM、中文OCR均已验证。软件/固件/视频代表链接 HEAD 返回200，不代表全库资源逐个下载或硬件兼容已实测。

仍需注意：复杂客户语言不做自动工程推理；原始案例条件不完整时保留参考和缺项；已知未支持的配单硬件分支继续保护。本地OCR依赖Windows安装的识别语言；公开仓库不包含公司原件、客户会话、数据库、凭证或内部审查包。
