# Bonsai 27B 工程判断长期学习任务

2026-10-17 用户指定的二代核心任务。目标是学习工程师处理真实客户问题、选择证据、修正判断与停止猜测的策略，不是扩充 FAQ 或让模型记住公司事实。每次接续先读本页及 STATUS；实现入口为 v2/engineering-learning。

## 两条知识线

公司事实（产品能力、版本、参数、操作和历史案例）由小灰机只读检索提供可定位证据，记录来源ID、版本、原文位置及适用条件。模型的理解不等于事实。

工程判断记录事实如何影响候选优先级、下一步查什么及原因、什么结果会改判。不得把相关案例宣布为当前故障原因；须核对型号、版本、发生条件、范围、反证与资料冲突。资料不足标未知，缺关键条件先追问，冲突保留冲突，无法继续可靠区分时交人工。

## 每案顺序

1. 收集脱敏客户原话，按来源/同一故障/近重复分组预先划分训练候选、验证和保留集。先前参与修复的题只能记回归。
2. 27B只看客户原话，输出事实、重要信息、候选、优先级、准备搜索、检索原因、关键追问，以及改判/停止条件。冻结原始请求与响应，异常不删。
3. 独立问工程师“如果你亲自接这个客户，你会怎么判断？”不展示模型答案或诱导工程师修正模型。继续问为什么、什么会改变方向、客户说不是怎么办、什么结果会放弃该方向、去微盘搜什么。区分当时判断与事后得知的结果。
4. 逐次检索和客户反馈入账。模型先更新自己的方向，再由工程师独立判断同一证据。保留原优先级、变化及原因；信息不足或实验混杂允许不改判。
5. 比较事实提取、空间切分、候选、优先级、检索、追问、依据、改判条件、停止条件。保存差异、为什么错及纠正所需证据，不只保存答案。未解决案例不得编最终病因。
6. 经人工核查的差异才进入训练候选。先用经验上下文做可回退对照，再评估是否需要权重训练；不能把保存笔记称为模型已经学会。验证/保留样本及其工程师答案不能进入训练或经验提示。

## 每次检索记录模板

```text
当前已知事实（原话、来源、观察/推测）：
当前候选方向及优先级：
为什么怀疑（事实关联，非确定病因）：
准备搜索（查询、已知型号/版本限定、工具）：
为什么搜索（希望区分什么、预期支持/反驳证据）：
搜索结果（真实ID/位置/版本；空结果也记录）：
适用核对（型号、版本、发生条件、范围、反证、冲突）：
是否支持/反驳/无关/不足：
新优先级及依据：
如不支持，下一步改搜什么及原因：
还缺什么、最有价值的追问、停止/人工条件：
```

## 对调实验记录模板

```text
交换对象及原故障位置：
保持不变的条件、同时改变的因素、可执行性：
交换前观察：
交换后观察（客户原话）：
故障跟随/不跟随/无法判断：
哪些方向上升、下降、保持及原因：
未排除的混杂因素与下一步：
```

对调是区分因果候选的实验，不是机械操作。未控制变量、观察不明确或交换对象本身不等价时，不能直接宣告唯一病因。采集程序不执行设备操作。

## 经验与差异模板

```text
案例ID、数据分组、来源、模型/提示版本：
现象、关键条件、尚未知条件：
模型初始事实、候选、排序、检索及原因：
工程师独立初判、依据、优先方向：
首选检查/检索及原因：
出现X则降低A；出现Y则转向B：
实际路径、反馈与最终结果（未解决照实记录）：
模型差异、为什么错、缺失的判断策略：
容易误判的情况、反例、边界、证据不足时：
经验状态、支持案例ID、反例ID、核验人、核验日期：
```

经验状态严格分为“已验证工程规律”“个人经验/暂未充分验证”“单个案例中的特殊处理”。新提炼默认暂未充分验证；明显特殊处理单独标记。升级须有多案例正例、反例检验及边界审查，留下人工核验记录；个案成功和工程师个人认可均不自动等于公司标准。

## 待验证先验

用户已提出：局部/整屏切分；调试或刚安装相对长期稳定后突发；最近换模组、动网线、升级固件、换电脑或改参数；同步/异步工作方式。它们用于提出可检验候选与寻找反例，不写成绝对规则，不给固定数值权重。尤其“长期正常后突然故障倾向硬件”“同步关注信号、异步关注节目/播放/控制”都须保留条件和反例。

## 评价口径

逐项报告样本数、可评数、通过数、未评原因和失败案例，不用一个总正确率替代。事实提取按可核验事实计 precision/recall，推测冒充观察另记；其他判断维度按独立工程师审查每案0/1/2（错误或有害/部分/充分合理），报告分布与分母，不用模型自评作成绩。

必评：事实提取正确率、故障空间切分正确率、首要方向接近度、检索方向接近度、追问价值、判断依据正确性、新证据后的方向更新、过早锁定率、无证据编造率、错误资料套用率、主动承认未知能力。合理的替代路径不因与工程师措辞不同判错。

过早锁定按未有充分区分证据却断言唯一病因的轮次/可评诊断轮次计；无证据编造和错误套用分别按含相应错误的回答/可评回答计。未知能力只在确实信息不足/冲突/超能力样本中评，同时报告充分证据下不必要拒答，防止一律“不知道”刷分。

重点单列“首次错误且获得有效反证”的案例：正确修正数/可评案例数；同时单列应保持方向的边界例，防止无条件改判。比较同一客户反馈前后的排序、依据和搜索方向；客户说“不是”而无实验条件不等于可靠排除。每批覆盖正例、反例、条件缺失、错型号/旧版本、冲突资料、空检索及对调结果不清。合成回归与新真实盲测分别报告。

## 当前边界与下一步

本次建立任务规范、提示和私有采集工具；尚无本任务新的真实客户基线、工程师独立标注或训练结果，不声称能力提升。下一步取得一条真实客户原话，先跑27B、冻结判断，再访谈工程师；不要把本文举例冒充真实训练案例。阶段完成仅公开源码/合成测试/脱敏摘要，实际客户及工程师记录留本地；GitHub同步不触发现网部署。
